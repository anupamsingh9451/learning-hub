------------------------------------------------------------
1. AAJ KYUN?
------------------------------------------------------------
Laravel apps ke slow hone ki sabse common wajah. Eloquent itna aasan hai
ki pata hi nahi chalta ek page 300 queries chala raha hai. Laravel interview
me ye lagbhag pakka poocha jaata hai. EduAssist me Institution -> Users
relationship banate hi ye problem tumhare saamne aayegi.


------------------------------------------------------------
2. CONCEPT
------------------------------------------------------------
Misaal: Tumhe 50 students ke ghar se unki copies laani hain.
    N+1 tareeka: pehle list lo (1 trip), phir HAR student ke ghar alag trip
               (50 trips) = 51 trips
    Smart tareeka: list lo (1 trip), phir ek gaadi bhej ke sab copies ek saath
               (1 trip) = 2 trips

Code me:
    $users = User::all();                       // 1 query
    foreach ($users as $user) {
      echo $user->institution->name;          // HAR user pe 1 query!
    }
    100 users = 1 + 100 = 101 queries.  Isliye naam "N+1".

Kyun hota hai? $user->institution "lazy loading" hai – jab tak access nahi
karte, load nahi hota; aur access karte hi ek nayi query.


------------------------------------------------------------
3. ILAAJ – EAGER LOADING
------------------------------------------------------------
    $users = User::with('institution')->get();
    // Query 1: select * from users
    // Query 2: select * from institutions where id in (1, 2, 3, ...)
    Ab loop me $user->institution pe koi query nahi. 101 -> 2 queries.

Aur tareeke:
    User::with(['institution', 'courses'])->get();      // kai relations
    Post::with('comments.author')->get();               // nested (comments ke author bhi)
    User::with('institution:id,name')->get();           // sirf zaroori columns
                                                      // (id ZAROOR rakho, warna jod nahi paayega)
    Institution::withCount('users')->get();             // sirf ginti chahiye
                                                      // -> $inst->users_count
    $users->load('institution');                        // object pehle aa chuke,
                                                      // ab baad me eager load ("lazy eager")

withCount vs with+count():
    $inst->users->count()  -> saare users memory me laaye, phir gine (bhaari)
    withCount('users')     -> DB ne hi gin ke diya (halka)


------------------------------------------------------------
4. N+1 PAKADNA – PREVENTION
------------------------------------------------------------
1) Laravel ko strict banao – AppServiceProvider::boot() me:
     use Illuminate\Database\Eloquent\Model;
     Model::preventLazyLoading(! app()->isProduction());
   Ab development me lazy loading hote hi EXCEPTION aayega – N+1 turant
   pakda jaayega. Production me band (users ka page crash nahi hona chahiye).
   (EduAssist me pehle din se ye laga do – achhi aadat.)

2) Tools: Laravel Debugbar (page pe query count), Laravel Telescope.

3) Quick check:
     DB::enableQueryLog();
     // ... code ...
     dd(count(DB::getQueryLog()));


------------------------------------------------------------
5. BLADE / API RESOURCES ME CHHUPA N+1
------------------------------------------------------------
Controller me sab theek, lekin Blade me:
   @foreach ($courses as $course)
       {{ $course->instructor->name }}       <- yahan N+1
   @endforeach
API Resource me bhi same:
   'instructor' => $this->instructor->name   <- har item pe query
   Behtar: controller me with('instructor'), aur resource me
   'instructor' => new UserResource($this->whenLoaded('instructor'))


------------------------------------------------------------
6. INTERVIEW ANGLE
------------------------------------------------------------
Q: "N+1 problem kya hai, kaise pakdoge aur kaise theek karoge?"
    Kya: list ki 1 query + har item ke relation ki alag query.
    Pakadna: Debugbar/Telescope query count, preventLazyLoading.
    Theek: with() / load() / withCount(); sirf zaroori columns.

Q: "Eager loading hamesha achha hai?" -> Nahi. Jo relation use hi nahi ho
    raha use load karna = faltu query + memory. Sirf wahi load karo jo chahiye.


------------------------------------------------------------
7. AAM GALATFEHMI
------------------------------------------------------------
- "Eager loading JOIN karta hai" -> with() aam taur par ALAG query
    (WHERE id IN (...)) chalata hai, JOIN nahi.
- "Sirf 20 rows hain, N+1 se kya farak" -> pagination ke saath 20 rows aur
    3 relations = 61 queries har page pe. Traffic badha to DB ro dega.
- "->count() aur withCount same hai" -> Upar section 3 dekho.

8. 5-MIN PRACTICE
------------------------------------------------------------
Apne kisi existing Laravel project (LMS/CRM) me:
    1. Koi list page dhundho jahan loop me relation access ho raha hai.
    2. Local pe Debugbar laga hai to query count dekho.
     Nahi hai to controller me  DB::enableQueryLog()  aur last me count.
    3. with() lagao, dobara count dekho. Number note karo – ye interview me
     sunane layak real story hai ("maine X page ki queries 140 se 6 ki").
