5. SERVER COMPONENT vs CLIENT COMPONENT
------------------------------------------------------------
    Default: har component SERVER component hai.
    - Server pe chalta hai, uska JS browser me nahi jaata (page halka).
    - Seedha DB query, secret keys use kar sakte ho.
    - useState, onClick, useEffect NAHI chalte.

    Client component: file ke upar "use client".
    - Browser me chalta hai.
    - State, events, browser APIs (localStorage) chalte hain.

        // app/products/page.tsx  (server)
        import AddToCart from './AddToCart';

        export default async function ProductsPage() {
            const products = await db.product.findMany();
            return products.map(p => (
                <div key={p.id}>
                    {p.name}
                    <AddToCart id={p.id} />
                </div>
            ));
        }

        // app/products/AddToCart.tsx  (client)
        'use client';
        import { useState } from 'react';

        export default function AddToCart({ id }: { id: number }) {
            const [added, setAdded] = useState(false);
            return <button onClick={() => setAdded(true)}>{added ? 'Added' : 'Add'}</button>;
        }

    Rule of thumb:
    - Zyada se zyada server pe rakho.
    - "use client" sirf chhote interactive tukdon (button, form, modal) pe.
    - "use client" wali file jo import karti hai, woh bhi client ban jaata
      hai. Isliye boundary jitna neeche ho sake utna achha.
    - Server se client ko props sirf simple data (JSON jaisa) jaa sakta
      hai, function nahi (Server Action chhod ke).

7. DATA FETCHING
------------------------------------------------------------
    Server component me seedha async/await:
        export default async function Page() {
            const res = await fetch('https://api.example.com/posts');
            const posts = await res.json();
            return <List posts={posts} />;
        }

    Ya seedha DB (Prisma/Drizzle):
        const posts = await db.post.findMany({ take: 10 });

    Caching control:
        fetch(url, { cache: 'no-store' })            har request fresh
        fetch(url, { next: { revalidate: 60 } })     60 sec tak cache
        fetch(url, { next: { tags: ['posts'] } })    tag se cache

    Next 15 me fetch by default cache NAHI hota (pehle hota tha). Next 16
    me "Cache Components" aaye: "use cache" likh ke function/component ko
    cache karte ho. Apne version ke docs ek baar zaroor dekho, yahi part
    sabse zyada badalta hai.

    Parallel fetch (waterfall se bachav):
        const [user, posts] = await Promise.all([getUser(), getPosts()]);

    Streaming (slow hissa baad me aaye, baaki page turant):
        <Suspense fallback={<Skeleton />}>
            <SlowReviews />
        </Suspense>

    Client component me data chahiye: TanStack Query ya SWR.

8. RENDERING KE TAREEKE
------------------------------------------------------------
    Static (SSG)    build time pe HTML ban gaya. Sabse tez. Blog, docs.
    Dynamic (SSR)   har request pe server pe banta hai. User-specific page.
    ISR             static, par har X second baad background me refresh.
                    revalidate se.
    Client (CSR)    browser me bana. "use client" + useEffect/Query.
    Streaming       page tukdon me aata hai (Suspense).

    Page dynamic kab banta hai? Jab cookies(), headers(), searchParams ya
    no-store fetch use karte ho.

    generateStaticParams – dynamic route ke pages build pe hi bana do:
        export async function generateStaticParams() {
            const posts = await getPosts();
            return posts.map(p => ({ slug: p.slug }));
        }

9. SERVER ACTIONS – FORM BINA API KE
------------------------------------------------------------
        // app/posts/actions.ts
        'use server';

        import { revalidatePath } from 'next/cache';
        import { z } from 'zod';

        const Schema = z.object({ title: z.string().min(3) });

        export async function createPost(prev: unknown, formData: FormData) {
            const session = await auth();
            if (!session) return { error: 'Login karo' };

            const parsed = Schema.safeParse({ title: formData.get('title') });
            if (!parsed.success) return { error: 'Title chhota hai' };

            await db.post.create({ data: parsed.data });
            revalidatePath('/posts');
            return { ok: true };
        }

        // form (client component)
        'use client';
        const [state, action, pending] = useActionState(createPost, {});
        <form action={action}>
            <input name="title" />
            <button disabled={pending}>Save</button>
        </form>

    DHYAN: Server Action ek public endpoint jaisa hai. Har action me
    login check aur validation khud karo.

19. GALTIYAN JO MAINE KI / GOTCHAS
------------------------------------------------------------
    - Hydration error: server aur browser ka HTML alag. Date.now(),
      Math.random(), window check render me. Fix: useEffect me ya
      client-only component.
    - Server component me useState lagaya, error. "use client" chahiye.
    - Layout me "use client" laga diya, poori site client ban gayi.
    - Secret NEXT_PUBLIC_ me daal diya, browser me dikh gaya.
    - Data update hua par page purana. revalidatePath/revalidateTag
      bhool gaya.
    - params ko await nahi kiya (Next 15+).
    - Server Action me auth check nahi kiya. Koi bhi call kar sakta tha.
    - <a> ki jagah <Link> nahi lagaya, poora page reload hua.

20. INTERVIEW ANGLE
------------------------------------------------------------
    Q: SSR, SSG, ISR me farak?
    A: SSR har request pe banata hai. SSG build pe ek baar. ISR static hai
       par set time ke baad background me refresh hota hai.

    Q: Server aur Client component me farak?
    A: Server component server pe chalta hai, JS browser me nahi jaata,
       DB seedha use kar sakta hai. Client component browser me, state aur
       events ke liye.

    Q: Hydration kya hai?
    A: Server se aaye HTML pe React ka JS judna, taaki button click jaise
       events chalne lagein.

    Q: Server Action kya hai?
    A: Server pe chalne wala function jise form ya button seedha call kare.
       Alag API route nahi banana padta.

    Q: next/image kyun?
    A: Resize, lazy load, modern format, layout shift se bachav khud.

    Q: Middleware kab use karte ho?
    A: Request se pehle redirect, auth ka halka check, locale, headers.

    Q: SEO kaise karte ho Next me?
    A: Server rendering, metadata/generateMetadata, sitemap.ts, robots.ts,
       sahi headings aur Open Graph images.
