1. EK LINE ME
------------------------------------------------------------
    Node.js browser ke bahar JavaScript chalane ka tareeka hai. Isse
    server, API, CLI tools aur scripts bana sakte ho.

    Misaal: Ek waiter jo order lete hi kitchen ko de deta hai aur turant
    agle table pe chala jaata hai. Khana ready hua toh wapas aake serve.
    Ek waiter, bahut saare tables. Yahi Node ka "non-blocking" tareeka hai.


------------------------------------------------------------
2. KYUN ZAROORI HAI / KAB USE KAREIN
------------------------------------------------------------
    - Frontend aur backend dono ek language (JavaScript/TypeScript) me.
    - Next.js, Vite, React tools sab Node pe chalte hain.
    - Real-time (chat, live notifications) me bahut achha.

    Kab lo:
    - REST/GraphQL API, real-time apps, BFF (frontend ke liye backend),
      scripts, CLI tools, AI agents ka backend.
    Kab mat lo:
    - Bahut CPU wala kaam (video encode, bada calculation). Event loop

------------------------------------------------------------
3. EVENT LOOP – NODE KA DIL
------------------------------------------------------------
    - Node ka JavaScript ek hi thread pe chalta hai.
    - File, network, DB jaisa slow kaam libuv (andar ki C library) ko de
      diya jaata hai. Woh background me karta hai.
    - Kaam pura hua toh callback queue me aata hai, event loop use chalata
      hai.

    Order samjho:
        console.log('1');
        setTimeout(() => console.log('2 timeout'), 0);
        Promise.resolve().then(() => console.log('3 promise'));
        process.nextTick(() => console.log('4 nextTick'));
        console.log('5');

        Output: 1, 5, 4 nextTick, 3 promise, 2 timeout

    Kyun?
    - Pehle normal (sync) code: 1, 5
    - Phir process.nextTick queue
    - Phir promise (microtask) queue
    - Phir timers jaisi macrotasks

    Event loop ko block mat karo:
        // GALAT: bada sync loop ya fs.readFileSync request ke andar
        // SAHI: async API (fs/promises), bhaari kaam worker thread me

5. MODULES – ESM vs COMMONJS
------------------------------------------------------------
    ES Modules (naya, recommended). package.json me "type": "module":

        export function add(a, b) { return a + b; }
        export default class Calc {}

        // app.js
        import Calc, { add } from './math.js';     // .js extension zaroori

    CommonJS (purana, bahut code me abhi bhi):

    ESM me __dirname nahi hota:

        import.meta.filename

8. ASYNC – CALLBACK SE ASYNC/AWAIT TAK
------------------------------------------------------------
    Callback (purana, "callback hell" banta tha):
        fs.readFile('a.txt', (err, data) => { ... });

    Promise:
        fetch(url).then(r => r.json()).then(show).catch(handle);

    async/await (aaj ka tareeka):
        async function getUser(id) {
            try {
                const res = await fetch(`https://api.example.com/users/${id}`);
                if (!res.ok) throw new Error(`HTTP ${res.status}`);
                return await res.json();
            } catch (err) {
                console.error('user nahi mila', err);
                throw err;
            }
        }

    Kai kaam ek saath:
        const [user, orders] = await Promise.all([getUser(1), getOrders(1)]);
        // ek bhi fail toh sab fail

        const results = await Promise.allSettled([a(), b()]);
        // sab ka result, fail ho ya pass

        const fastest = await Promise.race([fetchA(), timeout(3000)]);

    Galti: loop me await = ek ke baad ek (slow).
        for (const id of ids) await getUser(id);          // slow
        await Promise.all(ids.map(id => getUser(id)));    // tez

    Bahut zyada parallel (1000 calls) se API rate limit lagta hai. Batch
    me karo (jaise 10-10).

10. EXPRESS – API BANANA
------------------------------------------------------------
        npm i express

    Structure:
        src/
            server.js         app start
            app.js            express app, middleware
            routes/           URL -> controller
            controllers/      request/response handle
            services/         business logic
            db/               database connection
            middleware/       auth, error handler

    app.js:
        import express from 'express';
        import productRoutes from './routes/products.js';

        const app = express();
        app.use(express.json());                 // JSON body padhna
        app.use('/api/products', productRoutes);

        app.use((req, res) => res.status(404).json({ msg: 'Route nahi mila' }));

        app.use((err, req, res, next) => {       // error handler, 4 args
            console.error(err);
            res.status(err.status ?? 500).json({ msg: err.message ?? 'Server error' });
        });

        export default app;

    routes/products.js:
        import { Router } from 'express';
        const router = Router();

        router.get('/', async (req, res) => {
            const page = Number(req.query.page ?? 1);
            res.json(await listProducts(page));
        });

        router.get('/:id', async (req, res) => {
            const p = await findProduct(req.params.id);
            if (!p) return res.status(404).json({ msg: 'Nahi mila' });
            res.json(p);
        });

        export default router;

    Express 5 me async route ka error apne aap error handler tak jaata
    hai. Express 4 me try/catch ya wrapper lagana padta tha.

    Middleware = (req, res, next) wala function:
        function requireAuth(req, res, next) {
            if (!req.user) return res.status(401).json({ msg: 'Login karo' });
            next();
        }

13. AUTH – PASSWORD, JWT, SESSION
------------------------------------------------------------
    Password:
        import bcrypt from 'bcrypt';
        const hash = await bcrypt.hash(password, 12);
        const ok = await bcrypt.compare(password, hash);

    JWT (API ke liye):
        import jwt from 'jsonwebtoken';
        const token = jwt.sign({ sub: user.id }, process.env.JWT_SECRET, { expiresIn: '15m' });
        const data = jwt.verify(token, process.env.JWT_SECRET);

    Session vs JWT:
    - Session: server pe data, browser me cookie. Logout aasan.
    - JWT: token me data, server pe kuch nahi. Logout/revoke mushkil.
    - Web app ke liye httpOnly cookie wala session safe aur simple hai.

    Ready solution chahiye toh: Passport.js, Better Auth, Auth.js.

20. GALTIYAN JO MAINE KI / GOTCHAS
------------------------------------------------------------
    - await bhool gaya. Promise object hi aage chala gaya, ajeeb bug.
    - Loop me await, sab ek-ek karke, API slow.
    - readFileSync request handler me. Sab users ruk gaye.
    - Error handler me 4 arguments nahi diye, Express ne pehchana nahi.
    - res.json() ke baad bhi code chalta raha, "headers already sent".
      Response ke baad return lagao.
    - ESM me import me .js extension bhool gaya.
    - node_modules git me daal diya.
    - Memory leak: global array me data bharta raha, kabhi saaf nahi.

21. INTERVIEW ANGLE
------------------------------------------------------------
    Q: Node single threaded hai toh itni requests kaise sambhalta hai?
    A: JS ek thread pe, par I/O (file, network) libuv background me karta
       hai. Event loop callbacks chalata rehta hai, toh thread kabhi wait
       nahi karta.

    Q: process.nextTick vs setImmediate vs setTimeout?
    A: nextTick sabse pehle (current kaam ke turant baad), phir promises,
       phir timers (setTimeout), setImmediate check phase me.

    Q: Middleware kya hai Express me?
    A: (req, res, next) function jo request ko modify, check ya rok sakta
       hai. next() se aage bhejta hai.

    Q: Promise.all vs allSettled?
    A: all ek fail pe turant fail. allSettled sab ka result deta hai.

    Q: Stream kab use karoge?
    A: Badi file ya data jo memory me ek saath na aaye: upload, export,
       log processing.

    Q: CommonJS vs ESM?
    A: require/module.exports vs import/export. ESM standard hai, static
       hai (tree-shaking), top-level await chalta hai.

    Q: CPU-heavy kaam kaise karoge?
    A: worker_threads, ya alag service/queue (BullMQ) me.
