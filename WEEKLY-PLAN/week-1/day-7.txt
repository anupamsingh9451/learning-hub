TEST ME KYA BANANA HAI (samajh ke)
============================================================
Scenario: Student fees online bhar raha hai. Payment gateway (jaise Razorpay)
fail bhi ho sakta hai. Tumhe ek saaf, testable fee collection system banana hai.

1) Interface
     PaymentGatewayInterface {
         charge(string $studentId, int $amountPaise): string
     }
   -> transaction ID return karta hai.
   Note: paise me kyun (int)? Rs 499.50 = 49950 paise. Paisa ko float me
   rakhne se rounding galtiyan hoti hain (0.1 + 0.2 != 0.3). Isliye paise =
   hamesha integer. Ye real-world best practice hai.

2) Do implementations
   - FakeGateway    -> 'txn_' + koi random string return kare
                       (php.net pe random_bytes / bin2hex dekh sakte ho)
   - FailingGateway -> HAMESHA GatewayException throw kare

3) Service: final class FeeCollector
   - Gateway CONSTRUCTOR se aaye (DI!)
   - collect(string $studentId, int $amountPaise): string
       a) amount 0 ya kam  -> InvalidArgumentException
       b) gateway ->charge() call karo
       c) agar GatewayException aaye -> pakdo aur PaymentFailedException
          phenko, jo:
            - studentId apne paas rakhe (property + getter)
            - asli GatewayException ko $previous me chain kare

4) run.php – 3 cases, har ek ka saaf message print ho:
   - successful payment (txn id dikhe)
   - invalid amount (e.g. 0)
   - failed payment (FailingGateway ke saath)

5) answers.md (last 5 min) – 3 se 5 sentence:
   - Interface kyun?
   - Constructor injection kyun?
   - Gateway exception ko wrap (lapet) kyun kiya?
