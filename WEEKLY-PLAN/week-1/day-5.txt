CONCEPTS – AASAN BHASHA ME
============================================================
1) TRAIT = "copy-paste jo PHP khud karta hai"
   Kuch methods/properties jo alag-alag classes me chahiye, lekin un classes
   ka koi common parent nahi hai. Trait likho, aur `use` karke class me daal do.
       trait HasSlug {
           public function slug(): string {
               return strtolower(str_replace(' ', '-', $this->title));
           }
       }
       class BlogPost { use HasSlug; public string $title = 'Hello World'; }
       (new BlogPost())->slug();   // 'hello-world'
   Laravel me bahut dikhega: use HasFactory; use Notifiable; use RefreshDatabase;

   Trait vs base class vs interface – kab kya:
     Interface  -> sirf contract ("ye methods hone chahiye")
     Base class -> "is-a" rishta + shared state (Student IS A User)
     Trait      -> chhoti reusable ability jo kai unrelated classes me chahiye
                   ("has timestamps", "has slug")

2) declare(strict_types=1)
   Bina strict ke PHP "jugaad" karta hai:
       function double(int $n): int { return $n * 2; }
       double('5');   // strict OFF -> '5' ko 5 bana deta hai, chal jaata hai
                      // strict ON  -> TypeError!
   Strict ON = galat type turant pakda jaata hai, chhupe bugs nahi bante.

   Kahan lagta hai? PER FILE. Aur jis file me function CALL ho raha hai, us
   file ka setting maayne rakhta hai (jahan function define hai, wahan ka nahi).
   Isliye rule: HAR file ki pehli line:
       <?php
       declare(strict_types=1);

3) EXCEPTIONS – try / catch / finally
       try {
           // risky code
       } catch (SpecificException $e) {
           // sirf is tarah ki galti sambhalo
       } finally {
           // hamesha chalega (error ho ya na ho) – e.g. file band karna
       }

4) CUSTOM EXCEPTION – apni galti ka apna naam
   Built-in exceptions ki family (kuch kaam ki):
     Exception
       ├── LogicException
       │     ├── DomainException            (business rule toota)
       │     └── InvalidArgumentException   (galat argument diya)
       └── RuntimeException                 (bahar ki cheez fail – network, DB)
   Apni class:
       class OrderException extends DomainException {}
   Faayda: catch (OrderException $e) sirf order wali galtiyan pakdega, baaki
   galtiyan upar jaayengi (jahan unhe jaana chahiye).

5) NAMED CONSTRUCTORS – exception banane ka saaf tareeka
   `new` ki jagah static method jiska naam hi bata de kya hua:
       class OrderException extends DomainException {
           public static function outOfStock(int $productId): self {
               return new self("Product {$productId} is out of stock.");
           }
       }
       throw OrderException::outOfStock(42);
   Message ek jagah bana, aur code padhne me English jaisa lagta hai.

6) $previous – exception ki "chain"
   Jab ek low-level error ko apne high-level error me lapet ke phenkte ho, to
   asli error ko $previous me rakho, taaki debugging me asli wajah dikhe:
       catch (PDOException $e) {
           throw new OrderException('Could not save order', 0, $e);  // 3rd arg = previous
       }
       $e->getPrevious();   // asli PDOException milega
   (Ye Friday ke test me ZAROOR chahiye.)

7) KYUN har jagah catch (\Exception $e) BURI aadat hai?
   - Sab kuch nigal jaata hai – jo galtiyan asli bugs hain wo bhi chup-chaap
     pakdi jaati hain aur chhup jaati hain.
     (Side note: TypeError "Error" family se hai, Exception se nahi – isliye
     wo catch (\Exception) se pakda bhi nahi jaata.)
   - Pata nahi chalta kaunsi galti expected thi aur kaunsi nahi.
   - Sahi: sirf wahi exception pakdo jisko tum sach me sambhal sakte ho.

============================================================
COMMON GALTIYAN
============================================================
- declare(strict_types=1) pehli statement nahi hai (upar kuch aur likh diya)
  -> Fatal error. Ye <?php ke turant baad aana chahiye.
- Trait me private property – ye theek hai, trait use karne wali class ka
  hissa ban jaati hai.
- Named constructor me return type `self` aur `new self(...)` – `static` bhi
  chalta hai, abhi `self` theek hai.
