CONCEPTS – AASAN BHASHA ME
============================================================
1) DEPENDENCY kya hai?
   Jis cheez ke bina class apna kaam nahi kar sakti. EnrollmentService ko
   course dhundhna hai (repository) aur notification bhejna hai (notifier) –
   ye dono uski dependencies hain.

2) DEPENDENCY INJECTION = cheezein BAHAR se do, andar `new` mat karo
   Example: Chef (class) khud khet me sabzi nahi ugaata. Supplier sabzi DE
   jaata hai. Kal supplier badalna ho to chef ko kuch nahi badalna.

   BURA (tightly coupled):
       class ReportService {
           public function send(): void {
               $mailer = new SmtpMailer();      // andar hi new – fasa hua
               $mailer->mail('report');
           }
       }
   ACHHA (DI):
       class ReportService {
           public function __construct(private MailerInterface $mailer) {}
           public function send(): void { $this->mailer->mail('report'); }
       }
       new ReportService(new SmtpMailer());    // production me asli
       new ReportService(new FakeMailer());    // test me nakli!

   Bas yahi DI ka jaadu hai: test me asli email nahi bhejna padta.

3) FAKE (test double)
   Ek nakli class jo interface implement kare, lekin asli kaam ki jagah bas
   yaad rakhe kya hua. E.g. FakeMailer jo bheje hue messages ek array me
   rakh le. Test me baad me check karo: count($fake->sent) === 1.

4) REPOSITORY
   Data kahan se aata hai (DB, file, memory) – ye chhupane wali class.
   Aaj InMemoryCourseRepository = bas ek PHP array. Kal ko Postgres wala aa
   jaaye, service ko farak nahi padega (kyunki wo interface jaanti hai).

5) COMPOSER + PSR-4 AUTOLOAD
   Ab tak require_once likh rahe the. Composer ka autoload ye khud karta hai:
   "namespace Exercises\  ->  src/ folder". Class Exercises\Course apne aap
   src/Course.php se load ho jaayegi.

6) PHPUnit – test ka dhaancha
       <?php
       declare(strict_types=1);

       use PHPUnit\Framework\TestCase;

       final class CalculatorTest extends TestCase
       {
           public function test_it_adds_two_numbers(): void
           {
               // Arrange (taiyaari)
               $calc = new Calculator();
               // Act (kaam karo)
               $result = $calc->add(2, 3);
               // Assert (check karo)
               $this->assertSame(5, $result);
           }
       }
   - Method ka naam "test" se shuru ho (ya #[Test] attribute lagao).
   - Exception expect karna:  $this->expectException(SomeException::class);
     DHYAAN: expectException ke baad, exception wali line ke aage ka code
     NAHI chalta. To "exception aaya AUR notification nahi gaya" dono check
     karne hain to try/catch me pakdo aur catch ke baad assert karo.

7) SOLID – ek jagah (aaj ki exercise se jod ke)
   S – Single Responsibility : ek class ka ek hi kaam  (EnrollmentService sirf
                               enroll karti hai)
   O – Open/Closed           : naya channel = nayi class, Notifier ko chhedna nahi
   L – Liskov Substitution   : koi bhi NotificationInterface lagao, sab chale
   I – Interface Segregation : chhote interfaces (repository me sirf 2 methods)
   D – Dependency Inversion  : service interfaces pe depend kare, Email/SMS
                               jaisi concrete classes pe nahi
