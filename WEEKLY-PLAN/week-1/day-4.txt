CONCEPTS – AASAN BHASHA ME
============================================================
1) INTERFACE = CONTRACT / PROMISE
   Interface sirf batata hai "kaunse methods HONE chahiye", kaise kaam karein
   ye nahi batata.
   Example: Mobile charger ka socket (USB-C). Socket ko farak nahi padta
   charger Samsung ka hai ya Mi ka – bas USB-C hona chahiye.
       interface PaymentMethod {
           public function pay(int $amount): bool;
       }
       class UpiPayment implements PaymentMethod {
           public function pay(int $amount): bool { /* ... */ return true; }
       }

   Abstract class vs Interface – 3 bade farak:
     1. Interface me property/state nahi hoti; abstract class me ho sakti hai.
     2. Interface me (normally) method ki body nahi; abstract class me common
        code likh sakte ho.
     3. Class sirf 1 class extend kar sakti hai, lekin KAI interfaces
        implement kar sakti hai.

2) POLYMORPHISM = "ek naam, kai roop"
   Code sirf interface jaanta hai, asli object koi bhi ho sakta hai:
       function checkout(PaymentMethod $method) { $method->pay(500); }
       checkout(new UpiPayment());
       checkout(new CardPayment());   // checkout() ko badalna nahi pada!

3) VARIADIC PARAMETER  (...$items)
   "Jitne chahe utne arguments do" – andar wo array ban jaate hain.
       function total(int ...$prices): int { return array_sum($prices); }
       total(10, 20, 30);  // 60
   Typed bhi ho sakta hai:  PaymentMethod ...$methods

4) ENUM (PHP 8.1+) – fixed options ki list
   Jab value sirf kuch fixed options me se ho sakti hai (role, status, size).
   String 'admn' jaisi typo galti enum se bach jaati hai.
       enum Size: string {          // ": string" = BACKED enum (har case ki value)
           case Small = 's';
           case Large = 'l';

           public function label(): string {
               return match ($this) {
                   Size::Small => 'Small size',
                   Size::Large => 'Large size',
               };
           }
       }
   Kaam ke methods:
     Size::cases()        -> saare cases ka array
     Size::from('s')      -> Size::Small
     Size::from('xl')     -> ValueError THROW (galat value!)
     Size::tryFrom('xl')  -> null (error nahi, bas null)
   Kab kaun? Value pakka sahi honi chahiye -> from(). User input / shaq ho ->
   tryFrom() aur null check.

5) OPEN/CLOSED PRINCIPLE (SOLID ka "O")
   "Code EXTENSION ke liye open, MODIFICATION ke liye closed."
   Matlab: naya feature = nayi class add karo, purani class mat chhedo.
   Aaj ki exercise me: WhatsApp channel add karna ho to sirf nayi class –
   Notifier class ko haath bhi nahi lagana.

6) LISKOV SUBSTITUTION (SOLID ka "L")
   "Interface ka koi bhi implementation dusre ki jagah daalo, program
   theek chalna chahiye."
   Agar SmsNotification ka send() achanak exception phenk de jab Email wala
   nahi phenkta, ya bool ki jagah kuch aur de – to Liskov tootta hai.

============================================================
COMMON GALTIYAN
============================================================
- Interface ka method public na likhna -> interface methods hamesha public.
- Implementation me method signature alag kar dena (e.g. return type bool ki
    jagah void) -> Fatal error "Declaration must be compatible".
- Enum ko string se compare karna:  $role === 'admin'  -> false!
    Sahi:  $role === Role::Admin   ya   $role->value === 'admin'
